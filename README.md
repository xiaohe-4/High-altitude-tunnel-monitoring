# 高海拔隧道智能监测预警系统

这是根据项目方案设计的前端原型，聚焦于多模态监测、分级预警、MoMA 模型调度和实时事件管理等核心场景。

## 目录结构

- `index.html`、`styles.css`、`app.js`：监测仪表盘页面
- `api_server.py`、`server.py`：页面与接口服务
- `real_data.py`：现场环境表与设备故障表解析
- `docs/文档说明.md`：资料目录、各文件用途和整理约定
- `docs/MOMA接入信息.md`：已确认的 MoMA 接口信息
- `data/true_data/`：现场参考资料，按环境、事件、设备、通信、照明、报告分目录
- `data/videos/`：本地 MP4 视频
- `mock_data.json`、`data/tunnel_day_dataset.json`：方案演示合成数据

## 启动方法

在项目根目录双击或执行 `快速启动.bat`。脚本会使用 `.venv` 启动服务；若 8000 端口已在监听，则只打开页面。

也可以手动安装依赖后启动：

```bash
pip install -r requirements.txt
Copy-Item .env.example .env
python server.py
```

随后打开浏览器访问：

```text
http://localhost:8000
```

`python api_server.py` 也可直接启动同一服务。环境监测 API 提供 `CO`、`VI`、`WS`、`LA` 四类原表数值，设备故障 API 仅统计隧道名称为“色尔岗曲隧道”的记录。页面支持测点切换、视频播放和参考文件下载。

现场一氧化碳和光照历史表会单独给出核对结论，不作为演示异常。演示事件写在 `data/demo/simulated_events.json`，包含一氧化碳升高、照度骤降、温度升高和车辆停驶，页面会标明“模拟”，并且与现场结论分开。检出这些条目后会自动发给聊天补全接口；没有异常时不调用。路由表仍按类型标明策略：照度和温度走成本优先，一氧化碳走均衡优先，车辆停驶走效果优先。每一类单独短调用，避免一次长思考把输出额度用完。调用在后台进行。演示一点击就先显示备用结论，云端有可见文字后自动替换。已经拿到的结论会记在本机，再次点击立即显示。页面上的「重新提交 MoMA」会再请求一次。云端没有可见结论时，可显示事先写好的离线备用结论，该结论会标明不是本次云端返回。

`data/videos/车辆停驶故障_演示.mp4` 是按现场隧道画面风格生成的车辆停驶短片，不是现场录像。播放器默认播放该片。停驶判断直接读取播放器同一份 YOLOv8n 检测结果，不另行推理，也不上传原始视频。重新生成短片可运行 `python data/build_demo_video.py`（需要 `imageio-ffmpeg`）。页面下方的方案演示区是另一套样例，与现场曲线和模拟异常无关。云端实时同步尚未接入。

首次接入 MoMA 前，在本机 `.env` 中填入已轮换的 `MOMA_API_KEY`。接入范围和待确认项见 `docs/MOMA接入信息.md`。人工追问仍可选择常规巡检、异常复核、多源关联，以及成本优先、均衡优先、效果优先。这些策略映射到已确认的 `max_tokens`、`temperature` 和 `top_p`。调用使用流式返回并关闭思考，避免推理过程占满输出额度。等待上限由 `MOMA_TIMEOUT_SECONDS` 配置，默认 180 秒。图片输入、工作流/Agent 和 RAG 接口仍待官方文档确认。

真实资料是历史参考数据，并非实时采集流；曲线保留原表记录值，不做单位换算。风险分级、事件列表和模型矩阵仍是方案演示样例，不代表真实告警结论。MoMA 分析结果同样是辅助意见，需要人工复核。
